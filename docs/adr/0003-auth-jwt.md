# ADR 0003: регистрация и JWT-авторизация

## Статус

Принято.

## Контекст

API должен перестать быть открытым: нужны регистрация, вход и защита остальных ручек. UI ещё нет, клиенты — HTTP Client / Swagger / будущий SPA. Данные разных пользователей не должны смешиваться.

## Решение

- таблица `app_user` (email уникален, пароль только как BCrypt-hash)
- `POST /api/v1/auth/register`, `POST /api/v1/auth/login`, `GET /api/v1/auth/me`
- stateless JWT Bearer (`Authorization: Bearer …`)
- Spring Security 6: CSRF выключен, сессии не используются
- у `project` / `time_entry` / `money_entry` колонка `owner_id`; все выборки и мутации только в рамках текущего пользователя
- чужой ресурс → `404` (без утечки факта существования)

## Почему не иначе

- **один статичный API-token** — достаточно для личного сервера, но не даёт регистрацию и изоляцию; отложено как упрощение деплоя, не как модель продукта
- **server sessions / cookies** — хуже для будущего SPA и мобильных клиентов без лишней CORS/CSRF-возни
- **OIDC (Google и т.п.)** — позже, когда появится продуктный UI; локальный email/password остаётся запасным путём
- **refresh-token в БД** — следующий шаг, когда понадобится короткий access TTL

## Эксплуатация

Секрет подписи: `JWT_SECRET` (минимум 32 байта). В `local`/`docker` есть dev-значение; в `prod` обязательно своё.
